## 记账小程序（Taro 4 + 微信云开发）v1 落地

**技术栈**：Taro 4.3.2 + React 18 + TypeScript + Sass，webpack5 编译；数据层用微信云开发（云数据库 + 云函数）。

**关键决策**
- Taro 官方 CLI `init` 在非交互环境会被 SIGTERM 中断，改为从 `npm pack @tarojs/cli` 解压出内置模板，手工生成工程骨架（依赖版本与官方模板一致）。
- 金额统一以「分」为整数存储，展示时格式化，规避浮点误差。
- 明细列表：客户端直连数据库分页（每页 20 条，小程序端 `get()` 上限即 20）；统计：走 `stats` 云函数做服务端 aggregate，避免全量拉取。
- 静默登录：`login` 云函数用 `cloud.getWXContext().OPENID`，`users` 集合以 openid 作 `_id` 保证幂等，无弹窗无授权。
- 云开发实例获取：优先 `wx.cloud`，`Taro.cloud` 兜底（`src/services/cloud.ts`），并在 `types/global.d.ts` 里 `declare const wx: any`。
- 图标：Lucide（ISC）SVG → sharp 转 PNG；分类图标出彩色 + 白色选中态两套，tabBar 单独出 81×81。生成脚本 `scripts/gen-icons.mjs`，映射文件自动写 `src/assets/icons/index.ts`。
- tabBar 图标除 webpack 处理外，另在 `config/index.ts` 的 `copy.patterns` 里兜底拷贝到 `dist/assets/tabbar/`。

**踩坑记录**
- `sharp` 的 `@img/sharp-win32-x64` 可选依赖未装上 → 需 `npm install --include=optional sharp`。
- Taro 自带 `.d.ts` 缺 `miniprogram-api-typings`，`tsc --noEmit` 需 `skipLibCheck: true`。
- Sass `@import` 已弃用，页面样式统一改 `@use '../../styles/vars' as *;`。
- 构建会把 `project.config.json` 的 appid 从 `touristappid` 覆盖成一个具体值，需在开发者工具里确认是否为本人 AppID。

## 修复：开发者工具白屏 / `Cannot access 'c' before initialization`

**现象**：微信开发者工具里页面不渲染，控制台报 `ReferenceError: Cannot access 'c' before initialization`，栈顶 `Object.er` ← `Module.requestAnimationFrame` ← `app.js`。

**根因**：`@tarojs/runtime@4.3.2` 的 `dist/bom/raf.js`（及 `runtime.esm.js` / `index.cjs.js` 内联副本）里写了裸标识符：
`const _raf = _hasNativeRaf ? requestAnimationFrame : function(){}`。
而 `@tarojs/webpack5-runner` 的 `MiniWebpackPlugin.getProviderPlugin()` 用 ProvidePlugin 把 `requestAnimationFrame`
重定向成 `['@tarojs/runtime', 'requestAnimationFrame']`，于是 raf 模块初始化时读自己的导出 → const 处于 TDZ → 抛错。
（这是 Taro 官方 bug，4.3.2 为最新版，上游尚未修复。）

**修复**：`scripts/patch-taro-raf.mjs` 幂等修改上述三个文件，删掉 `_hasNativeRaf ? requestAnimationFrame :` 分支，
只保留 setTimeout 实现（小程序端 `_hasNativeRaf` 恒为 false，行为等价）；同时清理 `node_modules/.taro` 预打包缓存。
挂在 `postinstall`，且 `build:weapp` / `dev:weapp` 前置执行。

**复现/验证手法（可复用）**：用 Node 写 wx/App/Page/Component 桩 + Proxy，`require('dist/app.js')` 与各页面包，
即可在无开发者工具的情况下复现小程序端模块初始化错误。脚本示例见 F:/tmp/runpages.js（临时）。

## 三轮：-501000 真正的根因 = 多环境，云函数部署环境 ≠ 小程序默认环境

**定位手法（可复用）**：开发者工具本地缓存里能直接挖出环境 ID 列表，不必让用户手抄。

搜正则 `cloud1-[a-z0-9]{6,}`，其中 `qbaseInfo.envList` 字段同时给出 appid 与全部 env_id。

**事实**：AppID `wxf3dabfe233a259b7` 下有两个环境：
- `cloud1-d0g8ykn52bc4b36f2`（体验版，云函数 login/stats 部署在这里，控制台左上角显示为 `cloud1`）
- `prod-d6g6j3p677ff26615`（正式环境）

`wx.cloud.init()` 不传 env 时连「默认环境」，与部署环境不一致 → `-501000 the resource is not found`。

**改动**
- `src/config/cloud.ts`：`CLOUD_ENV = 'cloud1-d0g8ykn52bc4b36f2'` 显式固定，并注释两个 env 的用途。
- `src/services/auth.ts` 新增 `ensureLogin()`：会话内至少真正执行一次 `login` 云函数。

  `bill.ts`（分页/新增/删除）与 `stats.ts` 在取 DB / 调云函数前统一 await 它。
- `src/utils/error.ts`：-501000 文案改为「找不到」并直接打印当前连接的环境 ID，便于下次一眼判断环境错配。
- README 记录环境 ID 与 `-501000` 的判别方法（控制台复制 env id 逐字符比对，注意 l/1/0/O）。

**验证**：`tsc --noEmit` 0 error；`npm run build:weapp` 通过；env id 与新文案均进入 `dist/common.js`；四个包加载 OK。

## 四轮：预览二维码报 `invalid file: common.js SyntaxError: Unexpected token .`

**现象**：开发者工具「预览」生成二维码时报错，定位到 `common.js` 第 1 行第 41477 列。

**定位**：在该列打印字符，命中 `r?.categories` —— 可选链。工具真机预览/上传用的解析器只支持到 ES2015，
遇到 ES2020 语法即中断（它接受箭头函数/const，所以报错点出现在第一个 `?.`）。

**根因**：`package.json` 的 `browserslist` 是 Taro 模板默认的
`["defaults and fully supports es6-module", "maintained node versions"]`，
该目标声明浏览器原生支持可选链，Babel 因此不降级。改为 `["ios >= 9","android >= 4.4","chrome >= 53"]` 后全量降级。

**改动**
- `package.json`：修改 `browserslist`；`build:weapp` 末尾接 `node scripts/check-dist.mjs`，新增 `check:dist` 脚本。
- 新增 `scripts/check-dist.mjs`：用 acorn 以 ecmaVersion 5 解析 `dist/**/*.js`，失败则打印相对路径 + 行列号并 exit 1；
  没有 acorn 时降级为正则粗筛（`?.` / `??` / 逻辑赋值 / 箭头函数 / class）。
- README 增加「构建产物的语法目标」章节，说明 browserslist 与预览报错的因果关系。

**结果**：acorn 校验 ES5 / ES2015 / ES2020 三级全部 PASS；dist 462KB；四个包加载 OK。`project.config.json` 的 `es6:false` 可保持不变（产物已是 ES5，避免工具二次转译）。

## 首页去掉重复骨架屏（静默刷新）
**问题**：`useDidShow` 每次都 `setLoading(true)`，骨架屏条件又是 `loading` 一元判断，导致切 tab 回来 / 记完账返回都闪一次骨架。

**改法**（`src/pages/index/index.tsx`）
- state 拆成两个：`skeleton`（仅首屏骨架）与 `refreshing`（静默刷新的顶部细进度条）；`loadedRef` 记录是否已成功渲染过。
- `load(reset, showSkeleton = false)`：`showSkeleton || !loadedRef.current` 才走骨架，否则走 refreshing；切月显式传 `true`。
- `pendingRef` 排队：请求在飞时又触发 reset，等当前请求结束补一次；此时 `finally` 不关骨架，避免闪「空账本」。
- `useDidShow` 加 2s 节流（`lastLoadRef`），快速切 tab 不重复请求。
- 静默刷新失败不再清空列表：保留旧数据 + toast 提示（同一分钟内只提示一次，`errorToastRef`）；只有首屏失败才显示错误卡片。
- 删除成功后 `removeLocal()` 先本地摘掉并重算当天 expense/income、summary、count，再静默对齐服务端，避免行滞留。
- 样式：`.topbar` 加 `position: relative; overflow: hidden`，`.refresh-bar` 4rpx 橙色渐变 + `refresh-slide` 位移动画；预览页 `preview/index.html` 也加了同款，方便直接看效果。

**验证**：`tsc --noEmit` 0 error；构建通过 + `check-dist` 10 个产物 ES5 通过；Node 桩 5 个包加载 OK。

## 修复个人中心未适配状态栏高度（布局错位）
**根因**：`.nav` 在 scss 里写 `height: 88px`（→88rpx=44pt），又用行内 `paddingTop: statusBarHeight px`（真实 px）。全局 `box-sizing: border-box`，两个单位体系叠加：iPhone 14 Pro 状态栏 54px 时导航内容区高度 = 44-54 = 负值，标题溢出到个人信息行上；SE 上又只剩 24pt，规律性完全不同 → 每台机器都「差一点」。

**修法**：新增 `src/utils/system.ts`
- `getNavMetrics()` 返回 `statusBarHeight / navContentHeight / navTotalHeight / capsule / safeBottom`，结果缓存。
- `navContentHeight = (capsule.top - statusBarHeight) * 2 + capsule.height`（胶囊上下留白对称），clamp 40–64；拿不到胶囊回落 44。
- `Taro.getWindowInfo()` 优先，`getSystemInfoSync()` 兜底。
- 页面只用行内 px 写 `paddingTop` 与 `height`（行内不会被 pxtransform 转 rpx）；scss 的 `.nav` 不再写 height，只留 flex 居中。

**顺带修**：`.user` 左右 padding 32→28rpx，与下方卡片左边线对齐；导航 `z-index` 2→3（原来和 ScrollView 同级、后渲染的列表会盖住它）；滚动超过 6px 加 `.nav-solid` 毛玻璃底（blur 必须行内下发，scss 里写 `blur(18PX)` 虽不转 rpx 但 wxss 出现大写单位不保险）；`index.config.ts` 底色由橙紫改为 `#F4F5F7/#FFE7DA`。

**验证**：`tsc` 0 error；构建 + `check-dist` 10 产物 ES5 通过；Node 桩 5 包 OK；`preview/profile.html` 内置状态栏（44）+ 胶囊（top 48 / 右 7 / 87×32）模拟，Chrome headless 截图确认标题与胶囊垂直中心一致。

**注意**：bash 的 `/tmp` 与 Windows `F:/tmp` 不是同一目录，桩脚本在 `F:/tmp/runpages.js`；构建输出用 `> /tmp/x.log` 再看日志，**不要** `| tail` 直接截断（SIGPIPE 会杀掉构建，dist 只剩 project.config.json）。

## tabBar 改版：记一笔做成中间凸起按钮，统计降为次级页
**需求**：记一笔放到底部 tabBar 中间凸起；统计不再是 tab，入口移到首页顶部卡片 / 个人中心常用服务。

**方案**：微信原生 tabBar 不支持凸起，必须 `tabBar.custom = true` + `src/custom-tab-bar/` 自定义组件（Taro 会自动把它当组件编译，见 MiniPlugin.js:1085）。
- `app.config.ts`：`tabBar.custom: true`，`list` 只保留两个**真实 tab**（`pages/index/index`、`pages/profile/index`）。**关键坑**：写进 `tabBar.list` 的页面会被当成 tab 页，之后只能 `switchTab` 打开；所以「记一笔」绝不能进 list，它是普通页面用 `navigateTo`。
- `tabBar.list` 仍要 2–5 项，因此用「2 个 tab + 中间绝对凸起按钮」的布局：`tab` flex:1 ×2 放在两侧，中间 `tab-center` 同样 flex:1，视觉上居中。
- `src/custom-tab-bar/index.config.ts` 必须写 `export default { component: true }`，Taro 才会把它原样输出成 `custom-tab-bar/index.json`；不写就是 `{}`，微信不认为它是组件，直接不渲染。
- 凸起实现：外层 `.tabbar` 高 `192rpx = 80 凸起区 + 112 条身`，`.bar` 白底贴底，按钮 `margin-top: -64rpx` 把它顶进凸起区，**按钮始终在外层盒子内**，避免自定义组件裁剪；外层 `pointer-events: none`，只有 `.bar` 和按钮 `auto`，凸起区两侧的点击仍能落到页面。
- 按钮加 128rpx 白色底座（`.plus-wrap`），与条身同色 → 视觉上是个「凸起」，同时挡住圆背后滚动的内容，避免文字从按钮边缘露出来。
- 高亮同步：tab 页被缓存后 tabBar 实例不重新挂载，`src/utils/tabbar.ts` 的 `syncTabBar()` 在 `useDidShow` 里广播 `Taro.eventCenter` 事件，组件监听后 `setState`；挂载时再按 `getCurrentPages()` 兜底一次。
- 自定义 tabBar 是浮层，页面要自己留白：首页 `padding-bottom: calc(230px + env(safe-area-inset-bottom))`，个人中心最后一个卡 `margin-bottom: calc(210px + env(...))`（必须 > 192rpx，否则被凸起按钮压住）。

## 体验版发布准备（代码收尾 + 构建 OOM 改 esbuild 压缩）

**需求**：把当前版本上传并设为体验版，问「需要改哪些内容」。

**代码侧收敛（3 处）**

- `services/cloud.ts`：`[cloud] 已初始化` 日志包进 `if (IS_DEV)`，体验版/正式版不再向用户侧打印环境 ID 与 AppID。
- `pages/profile/index.tsx`：`settingsItems` 改为数组 + `useMemo`，`云开发环境` 行与 actionSheet 项都只在 `IS_DEV` 出现（用 `Fragment` 包住「分割线 + 行」，否则隐藏后会出现双分割线）。`preview/profile.html` 同步删掉该行与遗留的 `.foot` 孤行。

**sitemap**：`src/sitemap.json`（`disallow: *`）+ `app.config.ts` 的 `sitemapLocation: 'sitemap.json'` + `config/index.ts` copy patterns 拷到 `dist/`。私人账本不该被微信索引，同时消掉工具里「未找到 sitemap.json」的提示。

**构建 OOM（本次最坑）**：`taro build` 连续失败，exit 127/134，dist 只剩 `project.config.json`，日志里 `FATAL ERROR: MarkCompactCollector: young object promotion failed`（堆才 35MB 就挂）和 Rust 侧 `memory allocation of 56 bytes failed`。
- 判定是**环境内存**不是代码：`node -e "Buffer.alloc(400*1024*1024)"` 直接 `RangeError: Array buffer allocation failed`；系统 32GB、free 仅 2~3GB，commit 已被打满（explorer 单独占 9.8GB）。
- 逐个排除：`mini.terser.enable=false` → 构建通过（说明 terser 是峰值）；但产物未压缩，`check-dist` 报 `vendors.js:1297 Unexpected token` —— webpack 自己生成的 `{ __extends, __assign, __rest }` 对象简写不是 ES5，**压缩器必须能把语法降级**，不能图省事关掉。
- 最终方案：`config/index.ts` 加 `jsMinimizer: 'esbuild'`（Taro `BaseConfig.setMinimizer` 支持，走 `esbuild-loader` 的 `EsbuildPlugin`，默认 `target: 'es5'`）。`node_modules/esbuild@0.21.5` 已随依赖安装。`config/prod.ts` 清空。单进程原生实现，内存低一个量级。
- 结果：`npm run build:weapp` exit 0，`[check-dist] ✓ 11 个产物通过 ES5 解析`，dist 541KB（terser 版是 509KB）。

**README**：新增「上传为体验版（内部测试）」章节——构建 → 上传 → 选为体验版 → 加体验成员；不需要审核/备案/合法域名；必须核对 `bills`/`users` 为「仅创建者可读写」；体验版与开发共用 `cloud1-...` 数据不隔离。

**注意**：`MINIFY` 环境变量方案中途用过又废弃，最终只有 `jsMinimizer` 一处；`config/prod.ts` 保持空配置，别再往里加 terser 配置。

## 口径确认：上传代码包 = 根目录窗口 + miniprogramRoot(dist/)

- 开发者工具的「上传」**在仓库根目录的项目窗口里点**，不要单独打开 `dist/`。工具按根 `project.config.json` 的 `miniprogramRoot: "dist/"` 打包，`src/ node_modules/ preview/ scripts/ config/ cloudfunctions/` 天然不进包，不需要配 `packOptions.ignore`。
- 云函数不随「上传」走，仍是右键「上传并部署：云端安装依赖」；只改前端时不必重新部署。
- 体积自检：正常约 **541KB**；若显示接近 2MB 上限，说明打包目录选错。
- `dist/project.config.json` 是 Taro 产物（`miniprogramRoot: "./"`），会进包（约 1.5KB，无影响），但**绝不能把 dist 当项目根导入**——那样左边没有 `cloudfunctions`，就是当初 -501000 的成因。
