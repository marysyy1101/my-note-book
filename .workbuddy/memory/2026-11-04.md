## 需求可行性分析：自动导入微信账单

结论：全自动不可行（无第三方接口；「微信记账本」自动同步为微信支付自留能力），
可行方案是半自动文件导入——用户从「钱包 → 账单 → 下载账单」导出，小程序用
`wx.chooseMessageFile` 从会话选文件，端上解析 CSV/XLSX，去重 + 中性流水过滤 + 分类映射，
预览确认后经云函数批量写入 `bills`。

关键技术约束：
- 微信个人账单无开放 API；商户 `downloadbill` 仅覆盖本商户收款流水。
- 账单新增字段建议：`source: 'wechat' | 'manual'`、`externalId`（交易单号，去重键）、`importBatchId`。
- 当前 dist 537 KB，XLSX 解析库（SheetJS）建议走分包；纯 CSV 可零依赖。
- 中性流水（零钱充值/提现、理财通申赎、信用卡还款、转账）默认过滤，否则统计失真。
- 文案避免「自动同步微信支付账单」，防止与官方能力混淆导致审核风险。

待验证（Spike）：实际导出样本的扩展名、表头列名、是否有说明行、编码（UTF-8/GBK）、
金额是否带 ¥、「收/支」取值集合。

## 决策：不接入微信账单导入（2026-11-04）

用户判断「微信账单太乱（转账、红包、退款、消费混在一起），不适合接入」，需求终止，
不再排期。理由成立：噪声属于**语义不可判定**问题（转账是借款/还款/AA、红包是人情/娱乐），
解析层无法解决，自动导入只能拿到金额与时间，拿不到记账需要的经济含义，
用户仍需逐笔复核，成本高于手动记录。

若将来重启，唯一值得做的窄口径是：只看 `交易类型 ∈ {商户消费, 扫二维码付款, 小程序/公众号支付}`
且 `收/支 = 支出`，其余全部丢弃——仍解决不了"每月导出 + 人工确认"的成本问题。

替代方向（待定，优先级从高到低）：周期账目自动生成（房租/话费/会员/还款）、
一句话记账（自然语言解析）、最近商户与分类记忆 + 首页快捷记账。

## 图标体系重构：PNG 脚本 → lucide-react-taro 组件

原方案 `scripts/gen-icons.mjs` 用 lucide-static + sharp 预生成 PNG（颜色写死在脚本里，
选中态/深底场景都要另出一张图，如 `trash` 与 `trash-white`）。现改用 `lucide-react-taro@1.5.2`，
图标由组件在运行时把 SVG 转成 `data:image/svg+xml` 交给 `<Image>` 渲染，颜色/尺寸成为 props。

落地要点：
- `src/constants/icons.ts`：`ICON_COLOR` 色板 + `ICON_STROKE = 0.5`。
  旧 PNG 是「96px 画布 + 2px 描边」，等效 24 视口即 0.5；lucide 默认 2 会粗 4 倍，必须显式传。
  屏幕线条 ≈ size/48。
- `src/components/CatIcon.tsx`：分类图标 `key → 组件` 注册表（保留 kebab-case key，兼容历史数据），
  未知 key 回退 `Shapes`。
- 硬约束：data-uri 渲染拿不到 `currentColor`，颜色只能 `color` prop；`className` 只作用于外层 Image
  （布局/opacity），尺寸以内联 `width/height` 覆盖 scss 同名 class。
- 构建必须把该包纳入 babel：`config/index.ts` 的 `mini.compile.include` 指到 node_modules 路径，
  否则产物残留 `??`，微信开发者工具上传时报语法错误（`scripts/check-dist.mjs` 会拦住）。
- 摇树有效：主入口 764KB，实际打进 `vendors.js` 的只有用到的 31 个 svg 模板；未用图标（AArrowDown 等）已剔除。
- 产物 `dist` 492KB，`check-dist` 11 个文件通过 ES5 解析。
- 移除：`scripts/gen-icons.mjs`、`src/assets/`（68 个 PNG）、sharp、lucide-static 两个 devDep
  （lockfile 同步剪掉 27 条孤立条目，1227 → 1201）。
- 默认头像改为 CSS 渐变 + `UserRound`，不再预生成 PNG。
- 自定义 tabBar 走组件渲染（`tabBar.custom: true`，无需 tabBar PNG）；若将来改回原生 tabBar，
  图标仍需本地 PNG，得恢复一份生成脚本。

风险：`data:image/svg+xml` 在本机无开发者工具，未做真机渲染验证；若个别安卓端不显示 SVG data-uri，
需改回 PNG 或换 base64 变体。

注：本机 npm arborist 报 `Invalid Version:`（`canDedupe` 遇到占位包），`npm install` 无法直接使用，
本次采用「解包到 node_modules + 手工补 package.json / package-lock.json 条目」完成安装。

根因补充：lock 中存在无 `version` 的占位条目（含 `@parcel/watcher-darwin-arm64`、esbuild 的 AIX 平台包），
npm 10 去重时拿 undefined 比版本直接抛错。**最终解法**：删掉 `package-lock.json`、移走 `node_modules`，
用 nvm 下 node 20.19.0 自带的 npm 全新 `npm install` 重新生成 lock（1142 包），再跑一次验证幂等。
今后重装依赖请走 `npm ci`，不要手工改 lock。
