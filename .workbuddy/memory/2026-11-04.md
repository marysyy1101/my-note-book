# 2026-11-04

## 需求可行性分析：自动导入微信账单

结论：全自动不可行（无第三方接口；「微信记账本」自动同步为微信支付自留能力），
可行方案是半自动文件导入——用户从「钱包 → 账单 → 下载账单」导出，小程序用
`wx.chooseMessageFile` 从会话选文件，端上解析 CSV/XLSX，去重 + 中性流水过滤 + 分类映射，
预览确认后经云函数批量写入 `bills`。

关键技术约束：
- 微信个人账单无开放 API；商户 `downloadbill` 仅覆盖本商户收款流水。
- 账单新增字段建议：`source: 'wechat' | 'manual'`、`externalId`（交易单号，去重键）、`importBatchId`。
- 当前 dist 537 KB，XLSX 解析库（SheetJS）建议走分包；纯 CSV 可零依赖。
- 中性流水（零钱充值/提现、理财通申赎、信用卡还款、转账）默认过滤，否则统计失真。
- 文案避免「自动同步微信支付账单」，防止与官方能力混淆导致审核风险。

待验证（Spike）：实际导出样本的扩展名、表头列名、是否有说明行、编码（UTF-8/GBK）、
金额是否带 ¥、「收/支」取值集合。

## 决策：不接入微信账单导入（2026-11-04）

用户判断「微信账单太乱（转账、红包、退款、消费混在一起），不适合接入」，需求终止，
不再排期。理由成立：噪声属于**语义不可判定**问题（转账是借款/还款/AA、红包是人情/娱乐），
解析层无法解决，自动导入只能拿到金额与时间，拿不到记账需要的经济含义，
用户仍需逐笔复核，成本高于手动记录。

若将来重启，唯一值得做的窄口径是：只看 `交易类型 ∈ {商户消费, 扫二维码付款, 小程序/公众号支付}`
且 `收/支 = 支出`，其余全部丢弃——仍解决不了"每月导出 + 人工确认"的成本问题。

替代方向（待定，优先级从高到低）：周期账目自动生成（房租/话费/会员/还款）、
一句话记账（自然语言解析）、最近商户与分类记忆 + 首页快捷记账。
